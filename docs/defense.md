# Подготовка за защита

## Кратко представяне

Taskboard помага да разделиш проект на малки задачи и да проследиш напредъка през Kanban колони. Използва HTML, CSS, JavaScript, Bootstrap и Vite. Облачният backend е Supabase с Auth, PostgreSQL и частен Storage.

## Демонстрация

1. Влез с реален тестов акаунт, когато облачната конфигурация е завършена. Demo режимът трябва изрично да се представя като локално демо.
2. Създай проект и покажи трите колони.
3. Добави задача с описание, висок приоритет и срок.
4. Премести я между колоните и презареди.
5. Качи и изтегли файл.
6. Покажи търсенето и филтрите в общия списък.
7. Влез с admin и покажи специалните възможности.
8. Покажи SQL migrations, RLS policies и Git историята.

## Важни обяснения

- Всяка основна страница е отделен HTML entry, а не popup в един екран.
- `backend.js` отделя UI от Supabase и предлага едни и същи действия на page модулите.
- RLS проверява достъпа на сървъра. Скрит admin бутон не е защита.
- Ролята не идва от editable signup metadata.
- `tb_create_project` е транзакция: проектът и колоните се създават заедно.
- `tb_move_task` заключва проекта, за да не се състезават две промени на подредбата.
- Composite foreign key защитава task/stage принадлежността.
- Storage пази файловите bytes; таблицата `tb_attachments` пази описанието и връзката със задачата.
- Publishable key е предназначен за браузъра. Secret/service-role key никога не се включва в frontend bundle.
- Демото пази записи в localStorage и Blob файлове в IndexedDB; не трябва да се представя като доказателство за работеща облачна база.
