## Ръчен браузърен сценарий

Проверено на localhost:

1. Начална страница → demo → обзор с изчислени 3 проекта и 13 задачи.
2. Създаване на нов проект през формата → автоматични три колони.
3. Създаване на задача с висок приоритет и TXT файл.
4. Редактиране и преместване в „Завършени“ → напредък 1/1.
5. Refresh → задачата, колоната и файлът остават запазени.
6. Файлова страница → изтегляне на TXT файла; съдържанието се проверява спрямо оригинала.
7. Console error log е празен при този поток.
8. Responsive проверка на 390 px ширина, странично меню и вътрешно скролиране на таблиците.

## Регресия: премахване на файл в редактора (3 ноември 2026 г.)

В локалния browser demo е възпроизведен проблем: редакция на заглавие → премахване на attachment → потвърждение затваря редактора и губи текста. Поправката премахва само файловия ред, запазва редактора и dirty state и обновява изгледа след затваряне. По време на save/delete бутоните са блокирани срещу конкуриращи се операции. Грешка при refresh вече се отчита отделно от грешка при upload.

Проверени през UI с отделна тестова задача и TXT файл:

- Cancel в потвърждението запазва файла и въведения текст.
- Потвърденото премахване запазва заглавие, описание и избран High приоритет в отворения редактор.
- Save и browser refresh запазват редакциите; премахнатият файл не се връща.
- Cancel след премахването още предупреждава за незаписаните task промени. Discard запазва последната записана версия на задачата и премахването на файла.
- Изтриването на тестовата задача работи; временните demo данни са почистени. Console errors за тази проверка: 0.

Премахването на файл е отделна незабавна операция след потвърждение; Cancel на task редакцията не възстановява изтрития файл. Новата проверка е на общия UI през demo adapter, без промени по cloud schema или RLS. Предишните cloud проверки са описани по-горе.
